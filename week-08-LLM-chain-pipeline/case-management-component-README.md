## Overview

### What It Does

The Case Management component is the **decision and escalation layer** of $niper. It consumes flagged transactions from the Anomaly Detection workflow, analyzes them using AI (Groq LLM), and determines whether they warrant human investigation. For each flagged transaction, it generates an automated investigation case with a risk assessment, priority tier, and human-readable explanation — eliminating manual review of thousands of log entries and surfacing only what matters.

## Component Architecture

### Data Flow

```
Transaction Ingestion
        ↓
   [Airtable: Transaction Records]
        ↓
Anomaly Detection
(marks transactions with anomaly_score, risk_level, anomaly_reason)
        ↓
   [Airtable: Transaction Records updated with status = "case_created"]
        ↓
Case Management (THIS COMPONENT)
        ↓
   [Airtable: Fraud Investigation Case Records]
        ↓
   Dashboard + Notifications
```

### Input Contract

**Source:** Airtable `Transaction Records` table  
**Trigger:** Polling for `status = "case_created"`  
**Fields Read:**
| Field | Type | Example |
|-------|------|---------|
| `transaction_id` | String | `txn_12345` |
| `sender_id` | String | `user_789` |
| `recipient_id` | String | `user_456` |
| `amount` | Number | `5000.00` |
| `transaction_type` | String | `wire_transfer` |
| `timestamp` | Date | `2026-05-04T14:30:00Z` |
| `description` | Long text | `Urgent wire to unknown account` |
| `anomaly_score` | Number | `0.92` (0-1 scale) |
| `risk_level` | String | `high` / `critical` |
| `anomaly_reason` | Long text | `Unusual recipient, high amount, late-night timing` |

### Output Contract

**Destination:** Airtable `Fraud Investigation Case Records` table  
**Action:** Create new record with `status = "new"`  
**Fields Written:**
| Field | Type | Example | Notes |
|-------|------|---------|-------|
| `case_id` | String (auto) | `case_20260504_001` | Generated by n8n; format: `case_YYYYMMDD_###` |
| `transaction_id` | String | `txn_12345` | Link to original transaction |
| `sender_id` | String | `user_789` | Account holder under investigation |
| `recipient_id` | String | `user_456` | Receiving account |
| `alert_description` | Long text | `High-risk wire transfer to unverified recipient. Amount ($5,000) exceeds user's typical pattern by 300%. Timestamp (2:47 AM) falls outside normal activity window. Recommend immediate verification before processing.` | AI-generated via Groq |
| `confidence_score` | Number | `0.92` | Inherited from `anomaly_score` |
| `risk_level` | String | `critical` | Inherited from Anomaly Detection |
| `priority_tier` | String | `critical` | Computed: `critical`, `high`, `medium`, `low` |
| `escalation_flag` | Boolean | `true` | Determines if human escalation needed |
| `investigation_status` | String | `new` | Initial status; transitions: `new` → `in_progress` → `resolved` / `dismissed` |
| `audit_trail` | Long text (JSON) | `[{"action": "case_created", "timestamp": "2026-05-04T14:32:00Z", "reason": "anomaly_score >= 0.85"}]` | Timestamped log of all workflow actions |
| `created_at` | Date | `2026-05-04T14:32:00Z` | Case creation timestamp |
| `updated_at` | Date | `2026-05-04T14:32:00Z` | Last modification timestamp |

## Setup Instructions

### Prerequisites

You need:
- **Groq API Key** (LLM for case analysis)
- **Airtable Personal Access Token** (database read/write)
- **n8n Cloud account** (workflow automation)
- **Groq account** with API access (free tier available at https://console.groq.com)

### Step 1: Get API Keys

#### Groq API Key
1. Go to https://console.groq.com/keys
2. Create a new API key (or use existing)
3. Copy the key (format: `gsk_xxxxxxxxxxxxx`)
4. **Store securely** — you'll add this to n8n environment variables

#### Airtable Personal Access Token
1. Go to https://airtable.com/account/tokens
2. Create new token with scopes:
   - `data.records:read` (read Transaction Records)
   - `data.records:write` (write Fraud Investigation Case Records)
   - `schema.bases:read` (read table structure)
3. Copy token
4. **Note your Base ID** from your Airtable workspace URL

### Step 2: Set Up Airtable Schema

#### Create `Fraud Investigation Case Records` Table

In your Airtable base, create a new table named `Fraud Investigation Case Records` with these fields:

| Field Name | Field Type | Notes |
|------------|-----------|-------|
| `case_id` | Single line text | Primary key; n8n generates as `case_YYYYMMDD_###` |
| `transaction_id` | Single line text | Foreign key to Transaction Records |
| `sender_id` | Single line text | Account holder |
| `recipient_id` | Single line text | Receiving account |
| `alert_description` | Long text | AI-generated explanation |
| `confidence_score` | Number (0-100) | Inherited from anomaly_score × 100 |
| `risk_level` | Single select | Options: `low`, `medium`, `high`, `critical` |
| `priority_tier` | Single select | Options: `low`, `medium`, `high`, `critical` |
| `escalation_flag` | Checkbox | Boolean; true = requires human review |
| `investigation_status` | Single select | Options: `new`, `in_progress`, `resolved`, `dismissed` |
| `audit_trail` | Long text | JSON array of timestamped actions |
| `created_at` | Date | Timestamp when case was created |
| `updated_at` | Date | Timestamp of last update |

### Step 3: Configure n8n Workflow

#### Workflow Name
`Case Management - Transaction Analysis & Escalation`

#### Nodes to Create

**Node 1: Poll Transaction Records**
- **Type:** Airtable
- **Action:** List records
- **Base ID:** [Your Airtable Base ID]
- **Table:** `Transaction Records`
- **Filter:** `{status} = "case_created"`
- **Polling:** Every 5 minutes (adjust based on load)

**Node 2: Loop Through Flagged Transactions**
- **Type:** Loop
- **Input:** Output from Node 1

**Node 3: Format Groq Prompt**
- **Type:** Set
- **Purpose:** Build the AI prompt
- **Prompt Template:**
```
You are a fraud investigation specialist. Analyze this transaction and provide a concise risk assessment.

Transaction Details:
- Sender: {sender_id}
- Recipient: {recipient_id}
- Amount: ${amount}
- Type: {transaction_type}
- Timestamp: {timestamp}
- Description: {description}

Anomaly Signals:
- Anomaly Score: {anomaly_score} (0-1 scale; >0.7 = suspicious)
- Risk Level: {risk_level}
- Reason: {anomaly_reason}

Provide a 2-3 sentence explanation of:
1. Why this transaction is flagged
2. Specific risk factors
3. Recommended action (verify, block, monitor)

Keep the response concise and actionable for a fraud analyst.
```

**Node 4: Call Groq API**
- **Type:** HTTP Request
- **Method:** POST
- **URL:** `https://api.groq.com/openai/v1/chat/completions`
- **Headers:**
  ```
  Authorization: Bearer {{ env.GROQ_API_KEY }}
  Content-Type: application/json
  ```
- **Body:**
  ```json
  {
    "model": "llama-3.3-70b-versatile",
    "messages": [
      {
        "role": "user",
        "content": "{{ $node['Format Groq Prompt'].json.prompt }}"
      }
    ],
    "temperature": 0.7,
    "max_tokens": 300
  }
  ```

**Node 5: Parse Groq Response**
- **Type:** Set
- **Extract:** `$node['Call Groq API'].json.choices[0].message.content`
- **Result field:** `alert_description`

**Node 6: Compute Priority Tier**
- **Type:** Set
- **Logic:**
  ```javascript
  let anomaly_score = parseFloat(item.anomaly_score);
  let risk_level = item.risk_level;
  
  if (anomaly_score >= 0.85 && (risk_level === "critical" || risk_level === "high")) {
    return "critical";
  } else if (anomaly_score >= 0.75 || risk_level === "high") {
    return "high";
  } else if (anomaly_score >= 0.60 || risk_level === "medium") {
    return "medium";
  } else {
    return "low";
  }
  ```

**Node 7: Compute Escalation Flag**
- **Type:** Set
- **Logic:**
  ```javascript
  // Escalate if: anomaly_score > 0.80 OR risk_level is "critical"
  return (parseFloat(item.anomaly_score) > 0.80) || (item.risk_level === "critical");
  ```

**Node 8: Build Audit Trail**
- **Type:** Set
- **Value:**
  ```json
  [
    {
      "action": "case_created",
      "timestamp": "{{ new Date().toISOString() }}",
      "reason": "anomaly_score={{ item.anomaly_score }}, risk_level={{ item.risk_level }}",
      "groq_model": "llama-3.3-70b-versatile"
    }
  ]
  ```

**Node 9: Generate Case ID**
- **Type:** Set
- **Value:**
  ```javascript
  const now = new Date();
  const date = now.toISOString().split('T')[0].replace(/-/g, '');
  const counter = Math.floor(Math.random() * 999).toString().padStart(3, '0');
  return `case_${date}_${counter}`;
  ```

**Node 10: Write to Fraud Investigation Case Records**
- **Type:** Airtable
- **Action:** Create record
- **Base ID:** [Your Airtable Base ID]
- **Table:** `Fraud Investigation Case Records`
- **Fields Map:**
  ```json
  {
    "case_id": "{{ $node['Generate Case ID'].json.case_id }}",
    "transaction_id": "{{ item.transaction_id }}",
    "sender_id": "{{ item.sender_id }}",
    "recipient_id": "{{ item.recipient_id }}",
    "alert_description": "{{ $node['Parse Groq Response'].json.alert_description }}",
    "confidence_score": "{{ Math.round(item.anomaly_score * 100) }}",
    "risk_level": "{{ item.risk_level }}",
    "priority_tier": "{{ $node['Compute Priority Tier'].json.priority_tier }}",
    "escalation_flag": "{{ $node['Compute Escalation Flag'].json.escalation_flag }}",
    "investigation_status": "new",
    "audit_trail": "{{ JSON.stringify($node['Build Audit Trail'].json.audit_trail) }}",
    "created_at": "{{ new Date().toISOString() }}",
    "updated_at": "{{ new Date().toISOString() }}"
  }
  ```

**Node 11: Update Transaction Status (Optional)**
- **Type:** Airtable
- **Action:** Update record
- **Record ID:** From Node 1
- **Fields:**
  ```json
  {
    "status": "case_created"
  }
  ```
- **Purpose:** Mark transaction as processed so workflow doesn't re-process it

#### Environment Variables

Add these to n8n (Settings → Environment Variables):
```
GROQ_API_KEY=gsk_xxxxxxxxxxxxx
AIRTABLE_TOKEN=patxxxxxxxxxx
AIRTABLE_BASE_ID=appxxxxxxxxxx
```

#### Activate Workflow
- Toggle "Active" to ON
- Workflow will poll every 5 minutes for `status = "case_created"` records

## Known Limitations

### 1. **Groq API Rate Limits**
- Free tier: 30 requests/minute
- If you have >30 flagged transactions in 5-minute polling window, requests will be rate-limited
- **Mitigation:** Extend polling interval to 10-15 minutes, or upgrade Groq plan

### 2. **LLM Hallucination Risk**
- Groq may generate plausible-sounding but inaccurate explanations
- **Mitigation:** Always flag cases for human review; treat AI explanation as **supporting evidence**, not definitive proof

### 3. **Polling Delays**
- Workflow runs every 5 minutes (configurable)
- Case creation is not real-time; worst-case delay is ~5 minutes
- **Acceptable for fraud detection** (batch processing), but not suitable for real-time blocking

### 4. **Schema Assumptions**
- Workflow assumes Anomaly Detection will provide `anomaly_score` (0-1 float), `risk_level` (enum), `anomaly_reason` (text)
- If Joshua uses different field names or formats, workflow will break
- **Critical:** Confirm data contract with Joshua before Checkpoint 2

### 5. **No Webhook/Real-Time Trigger**
- Workflow polls Airtable; doesn't respond to real-time events
- If n8n is down or polling fails, Case Management won't process new transactions
- **Mitigation:** Switch to Airtable webhooks or message queue (post-Checkpoint 2)

### 6. **Audit Trail as Text**
- Audit trail stored as JSON string in Long Text field
- Querying/filtering audit events is difficult in Airtable
- **Better approach:** Separate Audit Log table (post-Checkpoint 2)

### 7. **No Notification System (Yet)**
- Workflow can be extended to send Slack/email alerts when escalation_flag = true
- Not implemented in Checkpoint 2 scope

## Troubleshooting

### Issue: Workflow hangs for 30+ seconds
**Likely cause:** Groq API is slow or request timed out  
**Fix:** 
- Check Groq API status at https://status.groq.com
- Increase HTTP timeout in n8n node to 60 seconds
- Check rate limits: `curl -H "Authorization: Bearer $GROQ_API_KEY" https://api.groq.com/openai/v1/models`

### Issue: Case Records not appearing in Airtable
**Likely causes:**
1. Polling is disabled (check n8n Active toggle)
2. No records with `status = "case_created"` exist (verify Anomaly Detection ran first)
3. Airtable token is invalid or expired
4. Wrong Base ID or Table name

**Fix:**
- Run n8n workflow manually (Test button)
- Check n8n logs for error messages
- Verify Airtable token still valid: `curl -H "Authorization: Bearer $TOKEN" https://api.airtable.com/v0/meta/bases`

### Issue: Groq returns empty or generic responses
**Likely cause:** Prompt is malformed or LLM didn't understand context  
**Fix:**
- Simplify prompt; remove jargon
- Add examples: "Example: 'High-risk wire to unknown account at 3 AM.'"
- Use temperature=0.3 instead of 0.7 (more deterministic)

### Issue: Escalation flags are all true/all false
**Likely cause:** Priority tier logic is wrong  
**Fix:**
- Manually check a few transactions: is `anomaly_score` actually high?
- Log intermediate values in audit trail
- Adjust thresholds (0.80 → 0.75, etc.)
